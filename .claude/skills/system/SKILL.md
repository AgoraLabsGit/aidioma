# /system

Meta-command for the development system itself—not product phases (`/plan`) and not phase execution (`/run`).

1. Read `AGENTS.md`, `Docs/System/development-system-v2.md`, and `Docs/System/COMMANDS.md`.
2. With Mike, name the process change: new/revised command, folder, file, or best practice. Apply MCOO;
   refuse archives, parallel registries, or undocumented homes.
3. Show proposed wording/paths before writing.
4. Update the minimum set: usually `COMMANDS.md`, `development-system-v2.md`, `AGENTS.md`, and the
   matching `.claude/skills/*` (and AIdioma development skill when command routing changes).
5. Large system installs (e.g. dashboard) still use a Roadmap phase + `/run`. `/system` is for bounded
   process onboard/revision.
6. Do not implement product/learner code. Publish via normal Git/`/close` when Mike directs a close;
   small `/system` edits may wait to ride with the next process commit Mike requests.
