# R-003 — Marketable MVP adversarial audit

Date: 2026-08-24  
Phase: PHASE-001  
Scope: `Docs/PRODUCT.md`, D-016 through D-023, `SPEC-F-LEARNING-LOOP`,
`SPEC-F-CONTENT-PIPELINE`, `SPEC-A-LEARNER`, and `SPEC-A-CONTENT`

## Verdict

**Proceed with conditions.** The proposed MVP is coherent and marketable because lessons,
collections, saved material, and translation all feed one production-first learning loop. The
MCOO cuts are real: one scored modality, no practice-direction choice, one dialect preference,
one saved-item model, and a deterministic scheduler.

Development should not begin as a broad page build. It should begin with dialect-neutral
content identities, the shared chat session contract, and retained evaluation evidence. Those
decisions prevent each surface from inventing incompatible content, progress, and grading.

## Claim attacks

| Attack | Risk | Finding | Required response |
|---|---|---|---|
| “Complete beginner to advanced” becomes a content-volume project with shallow pedagogy | High | A1–C1 is much larger than a normal MVP and is the largest schedule risk | Build and prove the pipeline on one vertical curriculum unit, then scale level by level. Do not market completeness until coverage receipts pass. |
| One translation modality becomes repetitive | Medium | More UI modes would add cost, but monotony could hurt retention | Vary unit length, context, register, retry timing, and feedback. Measure completion before adding modalities. |
| EN → ES only neglects comprehension | Medium | Production is the stronger shared MVP outcome, while lessons still contain Spanish examples | Record activity metadata and outcomes so a later receptive mode can be evaluated without prebuilding separate mastery now. |
| Removing direction-specific mastery loses useful information | Low | It avoids duplicate state but should not erase attempt context | Store the attempted activity type on evidence; aggregate confidence at concept/item level. |
| Dialect profiles drift or contradict one another | High | Model prompts alone cannot maintain Argentine voseo, regional vocabulary, and answer equivalence | Require structured profile coverage, cross-profile consistency checks, native-speaker sampling, and fail-closed promotion. |
| `es-419` hides country-level differences | Medium | It is a broad market profile, not a claim that Latin America is uniform | Flag country-sensitive terms and surface a concise alternative. Add country profiles only from observed demand. |
| AI graders are too strict, too generous, or inconsistent | High | Trust collapses if equivalent answers fail or wrong answers pass | Use promoted answer sets and deterministic normalization first; constrain AI to ambiguous cases and explanations; retain outcomes and offer report/correction. |
| Multiple AI reviewers share the same blind spot | High | More model calls are not automatically adversarial | Combine deterministic gates, distinct review rubrics/prompts, provider diversity where valuable, human sampling, and learner reports. |
| Adaptive practice traps learners in misses | High | Pure weakness ranking can feel punitive and narrow the course | Bound retry frequency, mix controlled new/recent material, avoid immediate repeats, and let learners change focus or exit. |
| Cold-start recommendations pretend to know the learner | Medium | No evidence exists at onboarding | Use selected/placed level, lesson order, and explicit focus until enough attempts exist; explain recommendations. |
| Saved-list organization grows into a knowledge-management product | Medium | Multi-list tagging, folders, and required save dialogs would overwhelm the core loop | Keep All saved plus at most one optional named list per item and automatic source/topic filters. |
| Translation saves pollute curriculum or mastery | High | Personal API output may be wrong, context-specific, or sensitive | Keep it personal, mark its source/profile, grant no mastery on save, and require separate promotion before curriculum reuse. |
| Translation language auto-detection fails on short ambiguous words | Medium | Single words can belong to both languages | Keep a visible swap control and preserve the corrected direction when saving. |
| Runtime model/API failure breaks the core product | High | Translation and ambiguous evaluation depend on external services | Pre-generate canonical curriculum, cache safe results where permitted, time out clearly, and never fabricate grading or progress. |
| Changing dialect destroys progress or duplicates the course | High | Dialect-coupled IDs would make profile switching a migration | Keep concept and meaning IDs dialect-neutral; regional renderings and accepted forms attach to them. |
| A content correction invalidates learner history | Medium | Promoted versions will change | Retain content version on attempts, keep concept identity stable, and re-queue only materially changed items. |
| “AI-powered” overshadows learning effectiveness | Medium | Marketing could imply an open tutor rather than a governed system | Lead with right-level practice and trusted regional Spanish; describe AI as the engine for adaptation, explanation, and content supply. |
| Sensitive translation text is retained unexpectedly | High | Learners may paste private material | Do not retain unsaved input as learning history; minimize operational logs and state the behavior plainly. |
| Five primary navigation surfaces still feel fragmented | Medium | A shared chat format alone does not create one journey | Give each surface one distinct entry purpose and return all active learning to the same workspace. Home offers one recommended next action. |

## Seam audit

| Seam | Contract that must be explicit before implementation |
|---|---|
| Content → lesson/collection | Stable concept and bilingual-item IDs, level, profile coverage, version, and promotion receipt |
| Content → evaluation | Accepted exact/normalized/regional forms, ambiguity policy, explanation evidence, and content version |
| Evaluation → learner state | Correct/close/needs-work outcome, attempt metadata, confidence effect, and no credit for lookup/save |
| Learner state → serving | Eligible scope, due/weak/new signals, retry bounds, and versioned policy reason |
| Translate → saved | Input language, bilingual pair, dialect profile, source, optional list, and personal/noncanonical status |
| Dialect preference → rendering | One profile resolution rule across lesson copy, prompts, answers, feedback, and translation |
| Content correction → history | Stable semantic identity, version retained on attempts, and explicit re-review rule |

## MCOO alternatives rejected

- Tracking knowledge separately for EN → ES and ES → EN
- A practice-direction chooser or a “Both” scheduler
- Multiple choice, flash cards, speaking, or free chat in the first release
- Separate lesson, collection, saved, and translation practice players
- Duplicating the full curriculum for every regional profile
- Required folder/tag selection during Save
- A learned recommendation model before an explainable baseline exists
- Publishing material because several models agreed without deterministic or human checks

## Conditions before implementation scale-up

1. Approve D-016 through D-023 as the product contract.
2. Prove one vertical unit end to end: structured objective → dialect renderings → promoted lesson
   and collection → chat practice → evaluation evidence → adaptive retry → saved practice.
3. Define measurable acceptance fixtures for Argentine voseo, regional vocabulary, equivalent
   answers, ambiguity, and level fit before generating curriculum at scale.
4. Define the A1–C1 coverage matrix and promotion threshold before making the completeness claim.
5. Instrument learner, content, evaluation, and provider failures separately so adaptation is
   not blamed for bad material or service outages.

## Residual founder decisions

No architecture decision is blocking. One commercial positioning decision remains for launch
planning: whether the first public release waits for the complete A1–C1 path or opens as an
explicitly labeled beta while higher levels are still passing the promotion pipeline. D-023
prevents claiming completeness early in either case.
