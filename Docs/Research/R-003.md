# Command audit richness vs V3 three gates

## Question

PHASE-007 started with a thin per-command audit column. Founder judged it too thin and asked to
recover prior audit procedures, run research + design panels, restore adversarial habit on
research/design/coding, enrich `/close` (security, composability, code quality, claims, MCOO,
seams), and design a real `/check` + close testing protocol.

## Evidence farmed

| Source | Keep |
|---|---|
| V2 Close audits (`git 47aeb867` `development-system-v2.md`) | Steward/Evidence/Seams/Learner-Surface **content** as nested lenses — not role names |
| `Docs.2/INDEX.md` | Design panel + independent adversarial before approval; composition cadence |
| `Docs.2/ARCHITECTURE.md` + product acceptance lists | Composability rules; concrete proof recipes (product, not System SSOT) |
| Living `system.md` §9–10 | Proof/Scope/Publish remain the only merge gates |
| Living `/audit` skill | Too thin; expand lens catalog, still not a merge gate |
| Adversarial panel on thin proposal | **FAIL** until Adv + named close lenses + `/check` protocol are explicit |

## Options

| Option | Strengths | Costs |
|---|---|---|
| A. Restore V2 named close roles | Familiar checklists | Role theater; dual PASS math; V3 already cut this for MCOO |
| B. Thin optional `/audit` only | Cheap | Fails founder intent; agents skip |
| C. **Nest rich lenses under Proof/Scope/Publish** + required Adv on research/design/close | Matches founder + MCOO; one merge authority | Skills/docs must name always vs conditional |

## Verdict

**C.** Keep Proof / Scope / Publish as the only merge gates. Nest richer always/conditional lenses
under them. Require independent adversarial on `/research`, `/design`, and `/close` phase-claims.
Path-aware `/check` records via activity `type: check` → `last_check`. Dashboard: honest Audits/
Tests + read-only Commands panel.

### Close lenses (nested)

| Lens | Gate | When |
|---|---|---|
| Outcome evidence | Proof | always |
| Adversarial phase claims | Proof | always |
| Security / privacy / a11y / AI tokens / perf / migration | Proof | path-triggered |
| path→spec Scope | Scope | always (computed) |
| MCOO binding | Scope | always |
| Seams / composability | Scope | always on build code; broader every ~2–3 caps |
| Code quality | Scope | code in diff |
| Publish hygiene + started CI | Publish | always |

### Per-command (summary)

| Cmd | Bar |
|---|---|
| `/research` `/design` | required adversarial + verdict/spec artifact |
| `/close` | required adversarial claims + full nested close + `/check` |
| `/run` | required proof + light seams/composition (Adv at close unless founder asks `/audit`) |
| `/fix` `/task` `/plan` `/ship` | required proof (reduced close when publishing) |
| `/system` | adversarial when amending audit/close/merge rules |
| `/audit` `/check` | are the audit/test surfaces |
| `/log` `/triage` `/status` `/launch` `/dashboard` `/handoff` | none |

### Open tension (founder decide)

Coding adversarial: founder “usually” audits coding work. Panel majority: durable Adv at `/close`
claims; `/run` gets seams, not a second full Adv every session. Alternative: required Adv before
accepting a coding slice inside `/run`.

### Testing protocol (summary)

1. `/check` = path-aware lanes mirroring CI (work / app / content); must not fix.
2. Record activity `check` → derive `last_check`.
3. `/close` = triage → `/check` → Proof/Scope/Publish (+ helpers) → smoke if build+app → PR/CI.
4. Design phases: usually work lane; Tests section honest not_run/N/A when no app paths.

## Revisit if

- Required Adv on every `/run` becomes the founder default (then amend matrix).
- Nested lenses still get skipped in practice (then add dry-run projection enforcement).
