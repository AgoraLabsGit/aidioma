# Kaikki vs Lexicon identity, collections, and DeepL

## Question

After choosing Kaikki (R-001), what does it replace in frozen Lexicon/architecture? Do words have
IDs? Can dictionary rows attach to lessons/collections? How does it compare to
[DeepL API](https://www.deepl.com/en/pro#api)?

Primary evidence: frozen `Docs.2/Specs/lexicon.md` (implemented LEXICON-001), stash entries
`lex-pedir` / `lex-ya-no`, contextual map `map-restaurant-…`, `Docs.2/ARCHITECTURE.md`,
TRANSLATION backlog posture.

## Options (roles, not vendors)

| Role | Owns | Kaikki? | DeepL? |
|---|---|---|---|
| A. Canonical Lexicon entry+sense | Reviewed `lex-*` + sense ids, EN glosses | No — candidate/QA only | No |
| B. Contextual map | Span → entry/sense on one prompt/lesson item | No | No |
| C. Offline lexical facts | POS, gender, lemma/forms check | **Yes (pinned)** | No |
| D. Runtime arbitrary translation | Live EN↔ES of unreviewed text | No | **Yes (later)** |
| E. Learner word DB | Observations, saved words, mastery | No | No |

## Verdict

**Kaikki does not replace the Lexicon, phrase layer, collection/lesson binding, or DeepL.**

Frozen posture already said it: Kaikki for *pinned offline POS/gender/lemma/form checks*; **do not
copy glosses/examples or use as runtime answer authority** (`Docs.2/Specs/lexicon.md` §Source and
API posture). R-001/D-014 stay: downloadable seed for *editorial* extract — not a shipped truth DB.

### IDs

| System | ID shape |
|---|---|
| AIdioma Lexicon | Stable strings: `lex-pedir`, sense `order-food` (not integers) |
| Contextual map | `map-…`, `ctx-…`; `LexicalTargetRef` pins entry/sense + versions |
| Kaikki raw JSONL | `word` + `pos` + sense list; **no stable sense ids** in raw dumps ([wiktextract #1016](https://github.com/tatuylonen/wiktextract/discussions/1016)) |

We assign AIdioma ids on review. Never key learner evidence to Kaikki page titles.

### Words DB vs phrases

- There is **no lexicon database today** — repo JSON under `content/lexicon/` (stash).
- **Words and phrases share one entry contract** (`kind: word | phrase`). Kaikki is mostly single
  lemmas; multiword like `ya no` still need **authored phrase entries**.
- Kaikki can *reduce editorial cost for common lemmas*. It does **not** remove the phrase catalog
  or contextual maps.

### Collections / lessons

Frozen rule: Lexicon **never stores** `lessonIds` / `collectionIds`. Binding is the other way:

```text
Collection/Lesson item  →  contextual map (spans + SourceRef)  →  lex entry/sense
```

Example: Restaurant map pins `collectionId: intermediate-restaurant` + item hash, then
`ordered`/`Pedimos` → `lex-pedir` / `order-food`. Auto-assigning Kaikki rows into lessons is
**not** the model; humans (or a later reviewed importer) create maps.

### DeepL vs Kaikki

| | Kaikki | DeepL API |
|---|---|---|
| Job | Offline dictionary facts | Online MT of arbitrary text |
| Latency/cost | Free dump; build-time | Per-char API; runtime |
| Stability | Pin dump hash | Output can drift |
| Ambiguity | Many senses; no task context | Sentence context helps |
| Curriculum authority | Never | Never (AI fallback only) |
| Fits | Lexicon authoring/QA | Translation surface / unreviewed help |

DeepL does **not** give stable word identity, POS/gender truth, or lesson binding. Kaikki does **not**
translate free learner text. Frozen Translation owner: reviewed lookup first; AI explicit and
non-canonical.

## Revisit if

- A paid Lexicala-style API replaces Kaikki for editorial QA with clearer commercial terms.
- Product approves shipping a large offline subset (then re-litigate CC-BY-SA + gloss policy).
- Translation phase proves DeepL must invent sense ids (it should not — still map into `lex-*`).
