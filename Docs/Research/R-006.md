# How to productize Praxis (extension + CLI)?

## Question

How should AIdioma productize Praxis (today: in-repo process + local dashboard) into a
shippable IDE-adjacent product — delivery vehicle, AI/execution spine, chat surface, and
workflow runtime — without rebuilding an IDE or competing as a coding-agent brand?

## Options

| Option | Strengths | Costs | Notes |
|---|---|---|---|
| A. **Theia/Electron IDE first** | Own shell + loop | Switch cost; IDE maintenance | Rejected for v1 |
| B. **Extension + IDE SDK spine** | Deep mid-run control | N adapters; host lock-in | Rejected as spine |
| C. **Extension + praxis CLI + agent CLI runners** | Portable; AIDLC-proven | CLI install matrix | **Chosen** |
| D. **Primary Praxis chat** (webview + `vscode.lm`) | Familiar chat UX | Duplicate; Cursor LM gap; LM ≠ coding agent | Rejected as primary |
| E. **Mastra/Temporal as v1 workflow runtime** | Rich TS workflows | Overkill if workers are external CLIs | Rejected for v1 |

## Verdict

**C** with thin custom stage machine in `praxis` CLI/core:

- **Keep:** Extension panels (MVP wrap vanilla dashboard), `praxis` CLI, ledger/gates/proof/close, activity, thin Runner ABI, optional host hooks as bouncers.
- **Outsource:** IDE shell; coding via `agent` / `claude` / `codex` CLIs.
- **No primary chat:** panels + native host agent + hooks; optional later VS Code `@praxis` Chat Participant.
- **Wedge:** proof/close + Work ledger (+ activity). Cost gates secondary; shared Docs/SSO later.
- **Multi-runner** = ABI intent; **MCOO:** prove one runner before day-one matrix.
- **ACP** optional later — not core ABI. **Mastra** only if later in-process Gateway agents.

## Adv

`ADV: WARN` — direction coherent; lock Revisit-if; multi-runner = ABI not day-one matrix;
hooks are half-deterministic/bypassable; thin host glue still required; leave Cursor vs VS Code
day-one, Marketplace vs Open VSX, and v1 SSOT (FS/SQLite/remote) **open**.

Blockers: none.

## Revisit if

- Extension host APIs block core panels/hooks for two milestones → reconsider Theia.
- CLI orchestration cannot enforce gates/proof reliably → reconsider SDK spine for one host.
- Multi-runner blocks MVP proof/close >1 milestone → ship one runner only.
- Marketplace/ToS forbids extension-spawned CLIs or project hooks → redesign distribution/execution.
- Paying users require first-party agent loop as primary surface → reconsider Gateway in-process path.
